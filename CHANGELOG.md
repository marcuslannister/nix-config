# Changelog

## Unreleased

- Update the dotfiles input, which drops the SSH `TERM` guard `.zshenv` briefly carried. The `xterm-ghostty` terminfo entry this repository already Declares in `home/home.nix` is what repairs the redraw corruption a muxy or Ghostty session sees over SSH; the guard rewrote `TERM` only on a host with no entry, so it stayed inert on every Declared host and would have masked a missing entry rather than exposing the Drift.
- Take scmpuff from nixpkgs on the Debian nodes instead of the local v0.7.0 pin. The pin adds `gitMinimal` and `which` as check inputs, which turns on scmpuff's testscript shell-wrapper suite, and those tests eval `scmpuff init -s`, whose output shells out to `/usr/bin/env` -- a path the Linux build sandbox does not provide, so the derivation could not build there at all and took every deploy to vm97 and vm98 down with it. The Macs build unsandboxed and keep the pin.
- Declare `graker` with its `eryouhao/tap` in the shared Darwin Homebrew module, so every Darwin host installs it.
- Deploy the shared Homebrew trust store to both activation and interactive paths, so the `muxy-app/tap` trust entry is available whether `XDG_CONFIG_HOME` is set or not.
- Declare `muxy` with its `muxy-app/tap` in the shared Darwin Homebrew module, so every Darwin host installs it.
- Declare `herdr` in `darwin/homebrew.nix`, absent from nixpkgs and bottled in homebrew/core for both aarch64 and x86_64 with no tap needed, so it reaches every Darwin host rather than the ARM Macs alone.
- Promote `httping`, `mole`, `nexttrace` and `tcping` from the three per-host Homebrew files into the shared `darwin/homebrew-arm.nix`, since all three ARM Macs carried the same four Exceptions with the same taps. As a side effect this fixes a pre-existing drift on mac-mini-m4 and macbook-pro-m1, both of which Declared `mole` without the `tw93/tap` it needs.
- Update the dotfiles input to give scmpuff's `git` wrapper a fallback command word, so a shell that replays the wrapper without `SCMPUFF_GIT_CMD` — Claude Code's shell snapshot is one — can run `git` at all rather than failing every call with "permission denied", and to add the pi continue setting.
- Update the dotfiles input to add the Emacs configuration directory to `PATH` for Anvil MCP clients.
- Make `tests/homebrew-keg-health.zsh` reject an installed keg whose missing or broken `opt` link leaves path-bound dependents unusable.
- Deploy the Go toolchain path and `IC_BOX` to all Zsh invocations from dotfiles.
- Update the dotfiles input to add Claude shortcuts, set the UTF-8 shell locale and Nix system path, and remove obsolete SCM Breeze loading.

- Remove SCM Breeze and Declare `scmpuff` in its place on every host, where it had been mac-mini-m1's alone. The pin to upstream v0.7.0 becomes `scmpuffModule` in `flake.nix`, one definition rather than an inline module on one host, and the three ARM Macs and the `default` fallback take it; the two Debian hosts take the same pin through `scmpuffPin`, built against unstable for the same reason the Macs are — scmpuff's `go.mod` asks for Go 1.26 and 25.05 carries 1.24. The Intel Mac is the one host that cannot have it and takes nixpkgs' 0.5.0 instead, unstable having no x86_64-darwin to borrow a newer Go from. 0.5.0 answers to the same `scmpuff exec --relative` and its `init -s` names the same subcommands, which is all the shell half asks of it. `ruby` leaves `common-darwin.nix` and both Debian home files in the same move, having been Declared for `~/.scm_breeze/install.sh` and nothing else; macOS still ships `/usr/bin/ruby` for anything that asks. That shell half is in `marcuslannister/dotfiles`, where `.zshrc` no longer sources `scm_breeze.sh` and `ls` keeps its numeric shortcuts through `scmpuff exec --relative`. What does not come back is the rest of what SCM Breeze wrapped: some 70 `g*` aliases, numeric expansion on `vim`, `cat`, `rm`, `cp`, `mv`, `ln`, `cd`, `less` and `code`, the Ctrl-x commit keys and the `c` repo jump, against the six aliases scmpuff Declares. Each machine also needs its own `~/.scm_breeze` clone deleted, with `~/.scmbrc` and `~/.git.scmbrc`.
- Stop Declaring `.config/tty7/config.json`, superseding the deployment recorded below. The tty7 server writes that file itself, so the symlink home-manager placed at generation 108 was a 42 KB regular file again by the next switch, which moved it to `config.json.backup` and restored the 2.3 KB Declared copy; because the backup always takes that one name, the switch after it would have overwritten the only copy. What each round displaced was 47 SSH profiles and their frecency, the command history frecency, and six settings keys the Declared copy predates, `ui_font_size` and `window_backdrop` among them. Nothing was published: the committed copy carries `"ssh_profiles": []`. The file is restored and left a regular file, which home-manager's cleanup skips for not linking into a generation, so it survives every switch after one warning at the next.
- Read the linked keg's receipt in `tests/homebrew-drift.zsh`, not whichever one the glob returned first. A formula keeps its older kegs until `brew cleanup` runs — six do on macbook-pro-m1 — and each keg's tab names only the dependencies of that build, so the closure the test walks, and with it every Adopted verdict, depended on directory order. `glib` proves the cost: its 2.88.1 tab names three dependencies and its linked 2.88.3 tab names four, so picking the older one would have reported `json-c` as Adopted when it is a dependency of a Declared Leaf. `$prefix/opt/<name>` is the keg Homebrew has linked, so its tab describes what the Mac uses; the newest tab is the fallback where there is no opt link. A damaged tab now also skips to the next keg instead of abandoning the formula.
- Add `tests/homebrew-keg-health.zsh`, which fails when the receipts describe a dependency graph that cannot be true, so the drift test is never asked to walk one. Receipts are written at build time and never revised, so a tab drifts from the formula it came from and silently moves the Adopted line in either direction: naming too much widens the closure and hides an Adopted formula, naming too little invents one. The test reads the disk alone and reports three faults — a cycle, since a real graph is acyclic; a tab naming a formula with no keg, which stops the walk short; and an installed keg whose missing or broken `opt` link makes its stable Homebrew path unusable. It reports extra kegs without failing, now that they no longer decide which tab is read.
- Add `scripts/homebrew-leaves.py` to produce a machine's Leaves for adoption, since neither obvious source can. `brew leaves` refuses formulae from untrusted taps and then omits them, listing 4 on macbook-pro-m1 where 11 third-party command-line formulae had real kegs. `installed_on_request` records how a keg was once asked for and is never revised, so it over-reports: 26 wrong on mac-mini-m4, 23 on mac-mini-m1, and 5 wrong here including the `libtiff` that a repair had just reinstalled by hand. The script instead calls a keg a Leaf when no other installed keg names it, prints each one's tap because Declaring needs it, and with `--flagged` prints that machine's disagreements as the list of traps. It asks Homebrew nothing, so it runs on a Mac whose taps are not yet trusted — which is the state both minis reach it in.
